# HelloGitHub 类开源社区站 — 设计说明

**版本**：1.0  
**日期**：2026-04-08  
**技术栈**：PHP、Laravel、MySQL；前台 **Blade** 模板渲染。

---

## 1. 背景与目标

在独立实现的前提下，建设一个与 [HelloGitHub](https://hellogithub.com/) 定位相近的站点：发现与分享有趣、偏入门向的开源项目，支持月刊、榜单、文章、用户体系、投稿与审核、标签与多维筛选等能力。

**成功标准（摘要）**

- 用户可注册登录（邮箱 + GitHub OAuth），**绑定 GitHub 后方可提交或编辑自己的项目投稿**。
- 投稿经自动规则校验后进入人工审核，通过后公开并纳入后续定时同步范围。
- 月刊按期号组织（封面、目录、多篇站内文章），榜单与列表基于本地快照与可配置策略展示。
- GitHub 元数据通过 **仅定时任务** 批量更新，Token 可后续配置，限流与失败可观测。

---

## 2. 约束与工程约定

| 项 | 约定 |
|----|------|
| 运行形态 | **单体 Laravel 应用**，领域边界清晰，便于后续演进 |
| 前台 UI | **Blade**（可配合轻量前端增强，不强制 SPA） |
| 数据库 | MySQL；**不使用数据库外键**，关联在应用层维护 |
| 唯一索引 | 命名前缀 **`uniq_`** |
| 结构变更 | **不使用 Laravel Migrations 管理**；表结构演进由独立 SQL 脚本或运维流程执行，本文档仅描述逻辑模型与字段意图 |
| 字段命名 | 避免 MySQL 保留字作字段名 |

---

## 3. 架构概览

- **表现层**：前台（列表、详情、月刊阅读、榜单、文章）、用户中心（GitHub 绑定、我的投稿）、管理后台（审核、月刊与文章、标签与黑名单、同步与任务状态）。
- **领域模块**：用户与 OAuth、仓库快照、投稿与状态机、人工审核、月刊期号与文章、标签与关联、榜单视图与排序策略、GitHub 定时同步。
- **基础设施**：队列（建议 Redis + 任务监控）、计划任务（同步与榜单重算）、缓存（热门列表与榜单等读多写少场景）。

---

## 4. 功能模块说明

| 模块 | 职责 |
|------|------|
| 用户与认证 | 邮箱注册登录、GitHub OAuth、会话与权限；GitHub 与站内用户绑定关系及唯一性校验 |
| 仓库快照 | 平台收录的仓库及其从 GitHub 同步的元数据（stars、描述、更新时间等） |
| 投稿与自动规则 | 去重、黑名单、必填项、格式校验、简单关键词拦截；通过后进入待人工审核 |
| 人工审核 | 审核队列、通过/驳回及原因；操作留痕 |
| 标签与分类 | 标签管理、仓库与标签多对多；前台筛选 |
| 月刊 | 期号、封面与目录结构、期内多篇站内文章 |
| 文章 | 月刊内文章与一般文章（若产品需要区分，由实现阶段统一内容模型或子类型） |
| 榜单 | 基于本地快照字段与运营配置的排序与加权；定时重算 |
| 同步任务 | 仅定时批量更新已收录仓库；失败重试、限流与降级 |

## 5. 逻辑数据模型（草案）

以下为逻辑实体与主要关系，实际表名与字段以实现阶段为准；关联不靠数据库外键。

- **用户**：账号信息、与 GitHub 绑定标识（绑定后允许投稿相关操作）。
- **OAuth 账户**：与第三方提供商、外部用户标识的映射。
- **仓库快照**：平台内唯一仓库记录、GitHub 坐标、同步得到的统计与描述类字段、同步时间与失败信息摘要。
- **投稿**：提交人、目标仓库坐标、文案与状态（待自动校验、待人工审核、已通过、已驳回等）、驳回原因。
- **标签**、**仓库标签关联**：多对多。
- **黑名单**：用于自动规则（如仓库坐标或模式类配置，以实现为准）。
- **月刊期号**：期号、封面资源地址、目录结构（结构化存储）、发布状态。
- **文章**：归属期号（若适用）、标题、正文存储形式、排序、发布状态。
- **审核日志**：投稿标识、操作者、动作、备注与时间。
- **榜单配置**（若需要）：榜单标识、规则参数、最后计算时间。

---

## 6. 关键业务流程

**投稿**：用户完成 GitHub 绑定 → 填写投稿 → 自动规则 → 未通过则反馈原因；通过则进入待人工审核 → 管理员或编辑处理 → 通过后发布并可将该仓库纳入收录与后续定时同步集合。

**月刊**：运营在后台创建期号、维护封面与目录、发布多篇文章；前台按期号进入阅读流。

**同步**：计划任务按批次拉取已收录仓库列表，调用 GitHub API 更新快照；单条失败记录原因并继续批次；全局限流与 Token 缺失时的降级策略在实现中明确（如跳过本轮并告警）。

**榜单**：与同步解耦；在快照更新后或独立定时任务中按策略重算榜单结果并缓存。

---

## 7. GitHub 集成要点

- **Token**：配置于环境或安全配置中，初期可无 Token 时仅禁用或限能力并提示运维。
- **节奏**：仅定时批量更新，不在用户打开详情页时强制实时请求 GitHub。
- **容错**：重试、退避、单仓库隔离失败；后台可查看同步健康度。

---

## 8. 安全与合规

- OAuth 使用 state、HTTPS、回调域白名单；防 CSRF 与会话固定等按 Laravel 实践。
- 绑定关系防止重复绑定与盗绑（以业务规则与校验为准）。
- 管理操作审计（审核、标签与黑名单变更等）。
- 用户生成内容与上传资源（封面等）的类型与大小限制、存储路径策略在实现阶段定义。

---

## 9. 错误处理与可观测

- 同步与队列任务：结构化日志、失败率与关键告警（可选接入现有日志系统）。
- 自动规则拒绝：对用户展示可读原因；对运营可统计驳回类型。

---

## 10. 测试策略

- 自动规则：单元测试覆盖主要规则与边界。
- 投稿到审核：功能测试覆盖主路径与关键异常。
- GitHub 客户端：使用 HTTP 替身测试响应映射、重试与限流分支。

---

## 11. 风险与后续迭代

- API 配额与成本控制依赖 Token 与同步频率、批次大小 tuning。
- 全功能第一版范围较大，实现阶段可按里程碑拆分交付，但本文档范围以已确认需求为准。
- 若未来流量与团队规模上升，可将同步与搜索等子系统独立部署，当前架构保留清晰边界以降低迁移成本。
